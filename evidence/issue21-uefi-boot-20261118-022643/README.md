# DC-1 user-space virtio-rng split queue acceptance

Date: 2026-11-18

An unprivileged Driver Host process created a split virtqueue in DMA-backed
Memory, negotiated modern virtio features, submitted a device-writable
descriptor, notified virtio-rng through ABI 3.22, and reaped a real used-ring
completion.

```text
map iova=0x1000000 pages=1 writable=true
pte iova=0x1000000 index=0 entry=0x1497003
queue_setup offered=8 status=15 notify_off=0
  desc=0x1000000 avail=0x1000100 used=0x1000180
  desc_rb=0x1000000 avail_rb=0x1000100 used_rb=0x1000180 enable_rb=1
queue_complete desc_id=0 used_len=32 data_nonzero=32
[JSR-DC1] summary ... queue_work=true failed=0
[JSR-DC1-BASELINE] before free_frames=123988 ... pins=(0, 0)
  after free_frames=123988 ... pins=(0, 0)
[JSR-IOMMU-DMA] hardware_iommu=true ... translated=true
qemu_rc=33
```

The queue uses the process's opaque IOVA. The IOMMU maps descriptor, available
ring, used ring, and receive buffer addresses; device completion writes the used
index and all 32 generated bytes into Memory. Closing the DMA handle restores
bus-master state, removes the translated PTE, and releases IOMMU tables. Object,
pending-cleanup and pinned-frame counters return exactly to baseline.

This closes the user-space virtio-rng descriptor -> notify -> used-ring
completion slice in the controlled QEMU/VT-d environment. It does not close
physical Pixel 6a UFS/GPU/driver lifecycle, real hardware IOMMU fault injection,
multi-IOMMU production takeover, or the full LC-4 firmware matrix.
