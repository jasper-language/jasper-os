# issue #12 阶段 A：拓扑、异构资源与统一内存约束

- 基线：public/main `04f7391`
- 性质：长期研究的架构契约切片，不是“已支持大规模 CPU / GPU / HPC”。
- 本切片目标：先把身份、所有权、能力边界、拒绝规则和验证门槛固定下来，避免后续按固定 8 核或固定宏内核布局写死。

## 1. 非目标

本切片**没有**实现：

- 32/64/128/256/512/1024 核的真实启动与扩展验证；
- NUMA 感知分配、跨 NUMA 迁移或 x2APIC / 高 APIC ID；
- GPU 驱动、GPU 提交队列、GPU 内存或统一虚拟寻址；
- IOMMU / IOVA / DMA 映射；
- 跨节点共享内存、RDMA、MPI、OpenMP 或超算作业系统。

任何后续实现都不得以本文档存在为由宣称上述能力已支持。

## 2. 身份、作用域与失效

拓扑和资源不得只用一个全局数组下标表示。至少区分：

| 身份 | 作用域 | 失效/复用规则 |
|---|---|---|
| 硬件中断控制器 ID | 平台固件作用域 | 不得直接当作逻辑 CPU 下标；热插拔后需重新发现 |
| 硬件处理器 ID（APIC/hart/MPIDR） | 单个启动世代 | 设备树/ACPI 重新枚举时失效 |
| 逻辑 CPU ID | 当前内核启动实例 | 可与硬件 ID 建立只读映射；不得跨重启持久化 |
| NUMA / Socket / Die / Cache domain | 平台拓扑作用域 | 允许非对称层级和缺口；离线/退化必须可见 |
| 设备 ID（BDF 或其他总线 ID） | 总线/域作用域 | 复用必须带代次；旧句柄不能命中新设备 |
| 内存对象 ID | 进程/系统对象作用域 | 沿用现有 Handle/Rights、对象代次与所有权规则 |
| 跨节点对象 ID | 集群协议作用域 | 不是本地可解引用指针，需认证、所有权和故障语义 |

通用约束：

1. 硬件标识与逻辑标识必须显式转换；越界、未知、离线、旧代次均拒绝。
2. 容量不足时禁止静默截断。当前 `Topology.dropped` 只是诊断计数，不是支持更大规模的证明。
3. 热插拔/重配置必须使旧引用失效，并明确在途操作、迁移、取消和资源回收。
4. 对象身份可在不同执行域/节点间传输，裸指针不可。

## 3. 当前源码约束矩阵

| 编号 | 当前事实 | 对大规模/异构扩展的约束 | 当前处理 |
|---|---|---|---|
| TOPO-01 | `kernel-core/src/smp.rs` 的 `MAX_CPUS = 32`，`CpuSet(u32)` | 32 位位集合不是任意规模集合；增加位数必须同步所有定长数组、邮箱和对外容量 | 保持显式上限；超出不得伪报支持 |
| TOPO-02 | `Topology` 保存硬件 ID、逻辑下标及 `dropped/disabled` | 逻辑 ID 与硬件 ID 已分离，但拓扑只有平面 CPU 列表，尚无 NUMA/cache/GPU 边 | 扩展为拓扑图，现有列表作为 CPU 视图 |
| TOPO-03 | x86_64 SMP 的 `INDEX_OF` 固定 256 项，多处限制 APIC ID `< 256` | 高 APIC ID 需要 x2APIC / 更宽映射；不能只放大数组 | 未支持项显式拒绝，另立实现 |
| TOPO-04 | `KERNEL_SCHED` 仍是全局规范状态锁 | 每核热路径与全局控制面需继续分层；不能以绕过规范锁冒充 O(1) | 保留当前正确性；先建立权威所有者与迁移协议 |
| TOPO-05 | 页帧 `ALLOCATOR` 和内核 `HEAP` 各有一把全局锁 | 单机 NUMA 需要本地池、回退与带宽策略；跨节点不得共享该分配器 | 当前单机实现正确，不据此外推 NUMA |
| TOPO-06 | `ShootdownBoard` 是全系统单请求板；地址空间记录 `active_cpus` | 大拓扑需按实际运行集合定向、批量化并分层传播；全量目标总工作量存在 Ω(P) 下界 | 当前正确性保留，性能按目标集合度量 |
| TOPO-07 | `environment::ResourceKind` 已有 Cpu/Gpu/Accelerator/MemoryBandwidth | 资源类型建模不等于真实驱动、队列、内存或隔离已实现 | 只允许作为策略输入，不能发布假能力 |
| TOPO-08 | `abi/system-ids.txt` 仍有 memory buffer / DMA 预留操作 | 预留 ABI 不得被解释成可在不可信设备上安全开放 DMA | 未实现能力保持 unsupported |
| TOPO-09 | 默认任务容量、对象容量与内存预算分别存在 | CPU、任务、对象、内存、设备容量不得共用“越大越好”的隐含推导 | 每类容量独立校验并在启动期拒绝不满足组合 |

## 4. 三层协调模型

### 4.1 每逻辑 CPU

- 本地运行队列、热点状态、定时候选与无关全局规模的快速判断。
- 普通本地操作的目标是 O(1)，前提是权威状态已安全本地化且资源已预留。
- 任何“只持 leaf 锁”的发布必须满足 Issue #2 的规范线性化结论；当前不新增不安全旁路。

### 4.2 本地域

本地域可以是 NUMA 节点、缓存域、PCIe 根复合体或设备亲和域：

- 本地内存池和容量预算；
- 任务组和 CPU 预算；
- GPU/加速器提交队列；
- 首批候选选择、分区均衡和批量完成。

跨本地域的操作需要有界候选探测和独立计量，不能在每个 tick 重复全系统搜索。

### 4.3 跨域/跨节点

- 跨 NUMA 迁移、内存重定位、DMA/GPU 同步和全局策略属于低频、按需付费路径。
- 多节点中每台机器有独立内核；节点间通过显式协议通信。
- 远程对象/内存窗口必须保留网络错误、所有权、复制与延迟语义，禁止伪装成本地指针。

## 5. 执行资源与对象权限

CPU 任务、GPU 工作和设备内存不能共用同一种 CPU 运行队列：

- GPU/加速器使用带代次和 Handle/Rights 的设备身份发布；
- 计算工作走真实提交队列/完成事件，不能同步假接口冒充 GPU 已执行；
- 设备复位、队列取消、驱动死亡和进程退出必须确认 DMA 停止或隔离后才能复用页帧；
- CPU 与设备共享“对象身份/权限/生命周期”，但保留不同的执行、驻留、一致性、抢占和故障语义。

## 6. 统一内存能力分级

| 等级 | 语义 | 当前状态 |
|---|---|---|
| U0 统一对象身份与生命周期 | 同一受权限保护的内存对象可被 CPU/设备引用；引用、配额、撤销、回收与隔离 | **部分基础**：已有 MemoryObject / 映射 / 共享引用 / 固定页配额，不代表设备引用已实现 |
| U1 显式映射与传输 | CPU RAM、设备内存间有方向、可见性、栅栏、错误恢复的复制/映射 | 未实现 |
| U2 共享虚拟寻址 | 设备使用与进程关联的虚拟地址；仍需设备页表、权限和缺页策略 | 未实现 |
| U3 受管理统一驻留与迁移 | 预取、固定、驱逐、迁移、并发缺页和回滚 | 未实现 |
| U4 可声明一致性范围 | 明确一致性域、原子宽度、排序、刷新/失效与同步 | 未实现 |

支持级别必须由真实平台能力和验证证据决定；不得因为 API 名称或资源枚举存在而静默升级。

## 7. 研究 Profile 与拒绝条件

研究 Profile 只描述未来配置维度，当前不装配：

- CPU HPC：NUMA 本地优先、计算核隔离、服务核与低 OS Noise；
- GPU HPC：CPU 提交核、GPU 队列、显存/拓扑放置、跨 GPU 同步；
- Service Node：网络、存储、故障治理服务，不要求每个计算节点携带全部后台服务。

必须拒绝：

1. 逻辑 CPU 数超过当前容量却继续启动；
2. 将硬件 ID 或旧代次当作当前逻辑 ID；
3. 未声明 IOMMU/等价保护却向不可信设备开放 DMA；
4. DMA 未静默就释放/复用页帧；
5. 服务停止或初始化失败后仍宣称能力可用；
6. 要求强时间/信息流隔离但目标平台无机制和证据；
7. 将 GPU 工作放入 CPU 运行队列；
8. 将网络远程内存当成本地可解引用内存；
9. 只把 `MAX_CPUS` 常量改大就宣称大规模支持完成；
10. 用单机 8 核 KVM 结果外推到 NUMA、256 核或集群。

## 8. 性能与验证口径

复杂度不是 p99.9 证明。必须分别测量：

- 本核热路径；
- 同 NUMA/本地域协调；
- 跨 NUMA/设备域；
- 全系统广播；
- fanout 的每目标分布和整批最慢目标完成时间；
- GPU 提交→开始/完成、DMA、跨节点消息与集合通信。

每次报告至少记录：提交、构建/Profile、硬件、固件、拓扑、NUMA 距离、SMT、内存、宿主或裸机、CPU 亲和、负载、时钟域、样本数、p50/p99/p99.9/p99.99/max、吞吐、扩展效率、锁争用与失败率。

宿主 KVM 是当前正式性能基线，但进程亲和不等于物理核心独占；TCG 只用于确定性和功能验证。高分位样本必须有足够数量并报告不确定性。
