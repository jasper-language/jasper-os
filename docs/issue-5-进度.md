## 1. 本片做了什么

| 项 | 内容 |
|---|---|
| `ring_backend::Kind` | 全部可经用户提交的后端（Now / Wait / Send / Recv / ExitWait / InterruptWait / SubscriptionWait），封闭枚举；内核自检的人工后端不在其中。 |
| `Kind::contract()` | 每个后端的静态契约：开始执行时的可中止性（`Exec`）、是否在提交内裁决终态、是否持有用户缓冲区。内部一致性：持缓冲 ⇒ 可中止且非瞬时；瞬时 ⇒ 不可中止。 |
| `Route` / `route` / `routes_well_formed` | 操作编号 → 后端。编号来自 ABI 生成表，本 crate 不写死。良构 = 编号非零（0 保留给人工后端）且互不相同、每个后端至少一条路由。 |
| 内核 `ring::ROUTES` | 唯一登记点，8 条路由；`const` 断言良构（编译即检查）。 |
| `check_sqe` | 原来的 8 项 `matches!` 列表改为 `route(&ROUTES, op)`，并返回后端种类。 |
| `prepare_user_work` | 原来按操作编号匹配、**未列出的操作落入兜底分支当作 recv**；现在按 `Kind` 穷举匹配，无兜底分支。 |
| `submit_in` | 可中止性与「持有用户缓冲区」取自契约（原来每个分支各写一次 `Exec::…`，另有一行手写的缓冲区判断）；人工后端仍由自检调用者指定。 |
| `submit_for`（内核自检入口） | 同样按 `Kind` 穷举。 |

### 后端生命周期契约（全部后端共用，写在 `ring_backend` 模块文档）

1. 校验（锁外）：标志位、路由存在、调用者被授予该操作；用户内存在此之前复制或固定。
2. 预留（对象表锁内，原子）：在飞配额、控制块、完成信用；任一失败 ⇒ 释放工作已持有的资源，不留半项。
3. 启动：按契约的可中止性调用状态机 `start`。
4. 推进：瞬时后端在提交内裁决；其余登记到等待源，由事件或到期推进。
5. 完成 / 取消：终态至多裁决一次（状态机保证）；取消可中止请求 ⇒ 中止后端。
6. 静止：持有用户缓冲区的后端先静止、后发布完成。
7. 释放：撤销等待登记、释放内部引用与固定；每个已启动后端恰好释放一次。

## 2. 新增后端需要修改的位置（前后对照）

| 位置 | 改动前 | 改动后 |
|---|---|---|
| 可提交操作列表（`check_sqe`） | 手写 `matches!` 列表，漏写 ⇒ 提交被拒为 unsupported | `ROUTES` 一行；漏写 ⇒ `const` 断言（每个后端至少一条路由）编译失败 |
| 用户提交解析（`prepare_user_work`） | 按编号匹配，漏写 ⇒ **静默落入 recv 兜底分支** | 按 `Kind` 穷举，漏写 ⇒ 编译错误 |
| 开始执行的可中止性（`submit_in`） | 每个分支手写 `Exec::…` | 取自 `Kind::contract()`，漏写 ⇒ 编译错误（穷举） |
| 是否持有用户缓冲区（`submit_in`） | 手写 `matches!` 判断，漏写 ⇒ 完成可能早于后端静止发布 | 取自 `Kind::contract()` |
| `Work` → `Kind`（`Work::kind`） | 无 | 穷举，漏写 ⇒ 编译错误 |
| 后端执行、推进、取消、释放（`submit_in` 执行分支、`retire_in`、`release_work_in`、`settle_in`、`abort_in`） | 各自 `match` | 第二片已收敛为 `launch_work_in` / `run_backend_in` / 每后端专属函数；`retire_in` 与分散中断并入被统一调度/释放取代 |
