- 日期：2026-10-28
- 分支：`dev/issue3-s1`
- 范围：第一片——冻结统一语义与事件层接口，并让每核硬件定时器编程这条真实路径改走统一仲裁器。x86_64 为唯一运行目标。
- 结论：契约、核心数据结构与六步验证链已完成；系统调用 / 异步环迁移到新身份表、宽容差请求的路由与大规模基准留待后续切片。

## 1. 统一请求语义（对外契约）

| 项 | 规定 |
|---|---|
| 时钟 | 单调时钟纳秒；所有期限都换算为绝对时刻 `at`。 |
| 相对期限 | `Request::relative(now, after)` = `now + after`；溢出直接拒绝，不饱和成「永不到期」。 |
| 容差 | `Precise`：到期后尽快处理，不得为合并推迟；`Tolerant { slack_ns }`：可在 `[at, at + slack]` 内任意时刻处理。最晚处理时刻 `latest` 溢出时饱和到 `u64::MAX`。 |
| 一次 / 周期 | `period_ns = 0` 为一次性；否则按 `at` 的相位重新装填到严格晚于当前时刻的第一个边界，错过的周期跳过、不累积补发。 |
| 身份 | `TimerId = (slot, generation)`。每次创建令该槽位代数加一；关闭后旧身份对装填、取消、到期一律无效。代数用尽（`u64::MAX`）的槽位永久退役，不再复用，因此不存在 ABA。 |
| 所有者与权限 | 每个定时器记录所有者；装填、取消、关闭要求调用者即所有者，否则 `NotOwner`，状态不变。 |
| 容量 | 表容量固定（无分配）；另有按所有者计数的 `OwnerBudget`。任务定时器与通用定时器使用各自独立的预算实例，一类耗尽不影响另一类。表满优先报 `Full`，其次 `Quota`。 |
| 取消与到期 | 调用方串行化（每张表一把锁）。取消返回 `Disarmed(原请求)` 或 `NotArmed`；与到期竞争时恰有一方生效，交付至多一次。 |
| 关闭 | 关闭同时撤下已装填请求并返回，供后端删除节点；预算恰好归还一次。 |
| 到期 | 后端以 `(slot, generation)` 回报；仅当身份有效、已装填且 `at <= now` 时交付一次（`Fired { owner, at, next }`）。陈旧或未到期返回空，不改状态。周期装填溢出时钟返回 `Overflow`，请求保持原样。 |

## 2. 对外语义与内部算法分离

- 应用只看到上表语义，看不到「堆 / 时间轮」。
- 精确期限继续使用现有按槽位索引的期限堆（每核一棵）。
- 宽容差普通超时是否引入分层非级联时间轮，按 issue 要求先做大规模普通超时基准再裁决；本片不实现、也不预留空的时间轮后端。

## 3. 每核仲裁

- `Arbiter::offer(at, urgency)` 逐个提交事件源，`program_at()` 返回各源「最晚处理时刻」的最小值，作为本核唯一一次性硬件定时器的编程时刻；无事件源时返回空，表示可取消本核定时器。
- 由于精确请求的最晚处理时刻就是 `at`，仲裁结果永远不晚于任何精确请求——容差不会推迟精确请求；宽容差请求在其窗口内被更早的事件顺带处理，从而合并中断。
- `needs_reprogram(已编程, 新时刻, now)`：时刻未变且仍在未来时不重复编程。
- `arm_delay(at, now, max)`：装填延迟至少 1 ns（已过期也立即触发），至多 `max`（更远的期限由中间唤醒重新仲裁）。

## 4. 本片接通的真实路径

- 调度器的每核纳秒定时器编程（`program_ns_local`）改为把各事件源交给统一仲裁器：本核纳秒期限堆的最早项、运行中任务的 tick 边界、纳秒预算耗尽时刻、旧 tick 唤醒/RT 回退、实时就绪抢占提示。当前全部按 `Precise` 提交，行为与改动前逐项一致；装填延迟与是否重编程改用契约函数。
- 既有 `deadline::next_period` 改为复用契约的 `next_boundary`（同一实现，`u32` 周期提升为 `u64`）。

## 5. 验证

六步验证链（`verification/toolbox/run-timer-event-suite.sh`，证据目录 `evidence/timer/timer-event-suite`）：

| 步 | 内容 |
|---|---|
| Verus/Z3 | 仲裁结果不晚于每个事件源的最晚处理时刻、不晚于每个精确请求、且等于某一事件源；周期边界是严格晚于 `now` 的第一个相位点；关闭后旧代数不等于新代数。负例「把容差加到精确请求上」必须验证失败。 |
| Proptest | 身份表对参考模型的差分（创建/装填/取消/关闭/到期任意序列，计数、预算、每个身份的已装填请求逐步比对）；仲裁 = 暴力最小值；装填延迟夹取；周期边界全值域性质与逐周期步进参考一致（含 `deadline::next_period`）。 |
| Miri | 两类预算、精确与宽容差混合、周期重装、关闭后复用、非所有者拒绝的完整生命周期。 |
| cargo-fuzz | 任意操作序列下：存活数 = 两类预算之和、已装填 ≤ 存活、陈旧身份无效且新代数严格更大、交付的请求确已到期、周期下一时刻对齐相位。 |
| Kani | 三源仲裁全值域不晚于任何最晚时刻且取到其一；关闭后旧身份不能触碰同槽位的新身份；一次性到期至多交付一次；周期边界性质（有界：`previous`、与 `now` 的差、周期均为 8 位值；全域由 Verus 与 Proptest 覆盖）。 |
| Loom | 调用方锁下「取消 vs 到期」恰有一方生效、交付至多一次；「关闭 vs 周期到期」关闭后无交付、计数与预算归零。 |

实测（2026-10-28）：Verus 8 verified / 0 errors，负例 1 error；Proptest 5 passed（每性质 512 例）；Miri 1 passed；cargo-fuzz 100 万次 0 崩溃（cov 133）；Kani 4 个 harness 全部 SUCCESSFUL；Loom 2 passed。`kernel-core` 宿主测试全部通过。

真实启动（x86_64 单处理器定点验收，默认启动已开启高精度定时器）：M1.1 启动自检、M1.2 时钟中断严格递增、M1.4 定时器抢占、T-2 基准与计时行均通过。多核检查留待合入前全量验收。
