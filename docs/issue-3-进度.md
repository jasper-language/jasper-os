- 日期：2026-10-28
- 分支：`dev/issue3-s1`
- 范围：第一片——冻结统一语义与事件层接口，并让每核硬件定时器编程这条真实路径改走统一仲裁器。x86_64 为唯一运行目标。

## 1. 统一请求语义（对外契约）

| 项 | 规定 |
|---|---|
| 时钟 | 单调时钟纳秒；所有期限都换算为绝对时刻 `at`。 |
| 相对期限 | `Request::relative(now, after)` = `now + after`；溢出直接拒绝，不饱和成「永不到期」。 |
| 容差 | `Precise`：到期后尽快处理，不得为合并推迟；`Tolerant { slack_ns }`：可在 `[at, at + slack]` 内任意时刻处理。最晚处理时刻 `latest` 溢出时饱和到 `u64::MAX`。 |
| 一次 / 周期 | `period_ns = 0` 为一次性；否则按 `at` 的相位重新装填到严格晚于当前时刻的第一个边界，错过的周期跳过、不累积补发。 |
| 身份 | `TimerId = (slot, generation)`。每次创建令该槽位代数加一；关闭后旧身份对装填、取消、到期一律无效。代数用尽（`u64::MAX`）的槽位永久退役，不再复用，因此不存在 ABA。 |
| 所有者与权限 | 每个定时器记录所有者；装填、取消、关闭要求调用者即所有者，否则 `NotOwner`，状态不变。 |
| 容量 | 表容量固定（无分配）；另有按所有者计数的 `OwnerBudget`。任务定时器与通用定时器使用各自独立的预算实例，一类耗尽不影响另一类。表满优先报 `Full`，其次 `Quota`。 |
| 取消与到期 | 调用方串行化（每张表一把锁）。取消返回 `Disarmed(原请求)` 或 `NotArmed`；与到期竞争时恰有一方生效，交付至多一次。 |
| 关闭 | 关闭同时撤下已装填请求并返回，供后端删除节点；预算恰好归还一次。 |
| 到期 | 后端以 `(slot, generation)` 回报；仅当身份有效、已装填且 `at <= now` 时交付一次（`Fired { owner, at, next }`）。陈旧或未到期返回空，不改状态。周期装填溢出时钟返回 `Overflow`，请求保持原样。 |

## 2. 对外语义与内部算法分离

- 应用只看到上表语义，看不到「堆 / 时间轮」。
- 精确期限继续使用现有按槽位索引的期限堆（每核一棵）。
- 宽容差普通超时是否引入分层非级联时间轮，按 issue 要求先做大规模普通超时基准再裁决；本片不实现、也不预留空的时间轮后端。

## 3. 每核仲裁

- `Arbiter::offer(at, urgency)` 逐个提交事件源，`program_at()` 返回各源「最晚处理时刻」的最小值，作为本核唯一一次性硬件定时器的编程时刻；无事件源时返回空，表示可取消本核定时器。
- 由于精确请求的最晚处理时刻就是 `at`，仲裁结果永远不晚于任何精确请求——容差不会推迟精确请求；宽容差请求在其窗口内被更早的事件顺带处理，从而合并中断。
- `needs_reprogram(已编程, 新时刻, now)`：时刻未变且仍在未来时不重复编程。
- `arm_delay(at, now, max)`：装填延迟至少 1 ns（已过期也立即触发），至多 `max`（更远的期限由中间唤醒重新仲裁）。

## 4. 本片接通的真实路径

- 调度器的每核纳秒定时器编程（`program_ns_local`）改为把各事件源交给统一仲裁器：本核纳秒期限堆的最早项、运行中任务的 tick 边界、纳秒预算耗尽时刻、旧 tick 唤醒/RT 回退、实时就绪抢占提示。当前全部按 `Precise` 提交，行为与改动前逐项一致；装填延迟与是否重编程改用契约函数。
- 既有 `deadline::next_period` 改为复用契约的 `next_boundary`（同一实现，`u32` 周期提升为 `u64`）。

## 8. 第三片：用户可见定时器对象 ABI（2026-11-07）

- ABI 从 `1.1.0` 升级到 `1.2.0`，旧快照保持不可变。
- 新增 `Timer` 对象：创建者进程所有，不可跨进程传递；`period_ns=0` 为一次性，非零周期按原相位推进，错过的周期跳过而不补发。
- 新增系统调用：65 `create`、66 `arm`、67 `cancel`、68 `wait`、69 `get`。`arm` 的 flags 0/1 分别选择相对时刻/单调绝对纳秒。
- 新错误 4139 `system.time.error.busy`：同一对象已有等待者；拒绝时不抢走原等待者，也不改变请求。
- `jasper-rt::time::Timer` 提供一次性、带容差一次性、周期、装填、取消、等待和剩余时间 API。
- 关闭最后句柄会撤下请求、唤醒等待者并归还容量；等待中的系统调用以 `async.cancelled` 终止。
- 固定上界为 256 个存活定时器对象。对象身份使用独立 `TimerId(slot, generation)`；严格递增编号在耗尽时拒绝，不回绕。

## 9. 第四片：宽容差真实路由与合并

硬件编程仍取各强制期限“最晚必须处理时刻”的最小值，因此精确请求不会被其他请求的 slack 推迟。宽容差请求另外登记到按最早可接受时刻 `at` 排序的固定容量期限堆。

真实定时器中断到达时，先用一次原子最小值检查跳过无关中断；只有容忍窗口已开始时才进入期限堆，弹出 `at <= now` 的登记并通过原有事件等待凭据唤醒任务。任务随后检查对象状态，在 `at` 后完成本次交付并推进周期相位。

因此，独占请求由 `at + slack` 兜底；窗口内出现其他真实定时器中断时可在共享中断中合并唤醒；任何请求都不会晚于 `latest`。关闭钩子、取消/改装路径和代次校验会清除已撤销登记，避免消费新请求。

[JSR-RT] summary ... reclaimed=true timers=0 coalesced=2 early=1 checks=28 failed=0

## 11. 大规模普通超时基准与后端裁决（Wave 9）

### 运行上限

当前通用定时器对象上限为 256；standard 配置下每个 Ring 的 Wait 身份表为 64。
通用定时器、任务纳秒等待和 Ring Wait 已各自使用固定容量 `TimerTable`，到期索引使用
每对象/每 Ring 的 `DeadlineHeap`，不再扫描执行中集合。

### 65,536 项混合期限压力

`kernel-core/tests/timer_backend_bench.rs` 在 65,536 个槽位上进行 16,384 次更新、
16,384 次取消和 49,152 次乱序到期弹出，共 163,840 次独立堆操作。固定种子，
release 构建，64 位宿主：

```text
timer-backend-heap n=65536 ops=163840 p50_ns=35 p99_ns=144 p999_ns=165 max_ns=7664
entry_bytes=24 index_bytes=2097152
```

该规模是当前 single Ring 容量的 1024 倍、通用定时器对象上限的 256 倍。即使在此规模，
三轮 p99.9 为 165/170/187 ns；存储主要是每槽 24 字节节点加一个位置下标，
`DeadlineHeap` 不分配、不保留陈旧节点。

### 同口径端到端负载

`user/bench` 的 `ring.wait_complete` 每轮提交 1 tick Wait、由真实定时器唤醒并收取完成；
`ring.wait_cancel` 提交长等待后同步取消。两项各 2048 样本，宿主 KVM：

|---|---:|---:|
| Wait 自然完成 p50 | 44,824,902 cycles / 12.45 ms | 45,119,248 cycles / 12.54 ms |
| Wait 自然完成 p99 | 53,617,258 cycles / 14.90 ms | 46,341,042 cycles / 12.88 ms |
| Wait 自然完成 p99.9 | 88,673,048 cycles / 24.64 ms | 48,056,230 cycles / 13.35 ms |
| Wait 自然完成 max | 94,806,988 cycles / 26.35 ms | 48,751,192 cycles / 13.55 ms |

同批 64×16 内核批量 Wait 压力：

### 裁决

**Wave 9 不实现分层非级联时间轮。**

理由：

1. 当前配置的真实并发上限远低于 65,536；在该数量级堆操作 p99.9 仍只有 170 ns。
2. 现有每对象/每 Ring 索引堆无分配、无陈旧节点，装填/取消是 O(log N)，登记等待取最早期限是 O(1)。
3. Wave 8 已把 Ring 收尾的任务表扫描降为 0；自然完成 p99.9 明显下降，没有证据显示中断次数或堆操作成为瓶颈。
4. 现在加入时间轮会增加级联/路由状态、取消节点回收和跨 CPU 迁移复杂度，却没有当前负载下的收益证据。

重新评估门槛：当实际配置需要单个 Ring 或单进程同时维持不少于 4,096 个活跃普通超时，
并且同负载 p99.9 的堆操作或定时器中断成本超过既定预算时，再以真实基准决定是否引入时间轮。
该结论是性能裁决，不是“时间轮永不实现”的永久承诺。
