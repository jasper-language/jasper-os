# jasper-os Rust 内核说明

> 本文描述当前**已实现并在 QEMU 中验证**的部分。未实现的能力只出现在 README 的路线表里，并明确标注。

---

## 一、分层

自下而上，只允许向下依赖：

| 层 | 位置 | 职责 |
|---|---|---|
| 指令集接缝 | `kernel/src/arch/` | `Platform` 契约（trait）：控制台、描述符表/异常、中断控制器与定时器、中断开关、上下文切换、页映射、地址空间、进入用户态。每个指令集一个实现目录，缺项即编译失败 |
| 纯机制库 | `kernel-core/` | 与硬件、引导方式无关的机制，宿主可测：对象与带世代计数的句柄表、权限位、等待集合、异步 ring、页帧位图分配、页映射契约、堆算法、模块装配、陷入分发、结构化追踪、自旋锁 |
| 内核基础设施 | `kernel/src/{console,irq,clock,boot}.rs` | UTF-8 控制台（整行原子输出）、逻辑中断线与延迟处理、时钟、与引导协议无关的交接信息 |
| 调度 | `kernel/src/sched/` | 机制（任务表、状态迁移、切换计划）与策略（`SchedPolicy`，默认 QoS 分级，纯决策位于 `kernel-core::sched`、宿主可模拟测试）分离；切换事件经观察者通知 |
| 内存 | `kernel/src/mm/` | 全局页帧服务、内核映射服务、内核堆（`#[global_allocator]`）、独立地址空间 `VmSpace` |
| 主流程 | `kernel/src/kmain.rs` | 架构无关的启动与里程碑演练序列 |
| 引导适配 | `kernel/src/main.rs` | 把 `bootloader` 的 `BootInfo` 转成中立的 `BootSpec`；换引导方式只改这里 |

**Core**（`arch/` 与 `main.rs` 之外的全部代码）不得出现 ISA 专有代码；验收脚本用 grep 机械检查，并带负向用例。

## 二、关键机制

### 调度
- 每个任务一块 16 字节对齐的内核栈：前 4 个槽位用静态栈（堆就绪之前可用），其余槽位在堆就绪后一次性预留（上限 64）；`switch_context` 只保存 callee-saved 寄存器与栈指针
- 抢占（默认开启）：定时器中断**先 EOI 再进入调度器**；每个 tick 记账、唤醒到期的睡眠任务、询问策略是否抢占；所有切换在关中断临界区内完成
- QoS 四档（交互 / 用户发起 / 工具 / 后台）：档间严格优先，高档被唤醒立即抢占；档内唤醒优先、再按近期 CPU 用量（周期减半）轮转；低档按千分比累积欠账，满一个 tick 即补给一个 tick（防饿死）；后台档被唤醒时只抢占空闲
- 档位经 `system.task.qos.set` 修改：降低或不变总是允许，提升需要创建方授予的上限；新任务继承创建者的档位；睡眠中的线程在所属进程开始终止时被提前唤醒
- 任务携带地址空间与内核栈顶：切换任务时同时切换地址空间、更新「从用户态进入内核时的栈」
- 优先级继承：任务区分自身档位与有效档位；等会阻塞的内核锁 `KMutex` 或等任务退出（`join`）时，等待者的有效档位沿等待链借给持有者（等待图整体重算，链长上限 8），放锁时直接交接给有效档位最高、同档先来的等待者并归还借来的档位；递归加锁、成环、等自己在阻塞前被拒且状态不变；持有者退出时唤醒全部等待者，锁可被接管
- 过载防护：CPU 组（通常一组 = 一个进程）各有一份上限令牌桶（每 tick 补充上限千分比份令牌、运行一个 tick 花 1000 份、桶容量 4 tick），令牌不为正时组内成员不参与选择、醒来也不抢占，当前任务被限速即换下；持有借来档位的任务豁免限速。看门狗为每个任务记录自上次主动让出（睡眠、阻塞、让出、退出）以来连续占用的 tick，越过阈值（默认 50）写入定长报告日志，只记录不处置

### 内存
- 页帧：位图分配器，帧 0 永不分配，保留区优先，重复释放 / 释放保留内存 / 未对齐均返回规范错误
- 内存压力：按全局空闲帧占可分配帧的比例分为正常 / 紧张（< 12.5%）/ 危急（< 5%），另保留 256 帧给内核；匿名内存申请按分配**后**的级别与请求者的有效档位准入（紧张拒绝工具与后台，危急只准交互，任何任务不得动用保留帧），判定在分配任何帧之前，被拒时报「内存不足」且不留改动；与每进程帧配额叠加
- 映射：Core 只定义中立权限位（写 / 执行 / 用户 / 全局）与 `PageMapper` 契约；x86_64 用 4 级页表实现
- 堆：按地址排序空闲链表 + 首次适配 + 释放合并；固定虚拟区间上按需映射增长
- 地址空间：每个空间有私有窗口，窗口外共享内核映射；销毁时回收全部私有页表帧

### 用户态
- 经 `iretq` 进入特权级 3；用户态的缺页、保护错误、无效指令**只终止该任务**，内核继续调度
- 事件以结构化标记输出：`system.task.faulted`

### 系统调用与用户程序
- 陷入指令在 `arch/`；Core 按 `system.<领域>.<对象>.<动作>` 名字分发，数字 ID 由人写在 `abi/system-ids.txt`，
  构建期校验命名并检查已发布的 ID 未被删除、改号或改名（违反即构建失败）
- 每个任务有可用调用集合（统一权限检查）；用户指针一律先校验再经物理映射复制
- 进程拥有地址空间、句柄表与帧；最后一个线程停止即退出并关闭句柄表；对象在全部强引用释放后由清理过程销毁
- 句柄权限只可降低；跨进程转移在同一把锁内先检查后提交

### 异步 I/O（`kernel-core::io`）
- 只有「提交 → 完成」：提交时即预留完成槽位，完成永不丢失
- 取消只能把请求从提交队列摘除一次，每个请求恰好一条终态完成，不会重复完成

### 用户态异步环（`kernel-core::async_ring` + `kernel/src/ring.rs`）
- 接口：`system.async.ring.create` / `system.async.ring.enter` / `system.async.cancel`；记录布局见 `kernel-core::ring_abi`
- `enter` 一次完成「提交一批 → 推进后端 → 收取完成」；完成队列是唯一的等待对象，没有就绪通知
- 请求 ID 在 Ring 内单调递增、永不复用、到上限拒绝；用户标签原样带回，从不参与匹配
- **完成信用**：每个被接受的请求预留一份信用，发布时占据完成队列，用户消费时归还；信用为 0 时提交原子失败（`cq_full`），
  被拒的提交不消耗请求 ID、不改任何配额
- 同步取消不占信用，信用耗尽时仍可用；取消结果区分 未开始 / 可中止 / 执行中（`in_progress`）/ 已完成（`already_completed`）/ 不存在（`not_found`）；
  已发布的终态保留最近 C 个用于区分后两者
- 访问用户缓冲区的请求：完成只在后端静止之后才可见
- Ring 进程私有（句柄不带 TRANSFER）；外部所有权归零或进程退出 ⇒ closing：拒绝新提交、取消可取消的请求、丢弃未消费的完成，
  不可中止的请求继续到自然结束；有未销毁的请求时 Ring 自身保活，最后一个请求销毁后才被清理
- 配额（开发默认值）：完成队列容量 ≤ 64、每进程 Ring ≤ 8、每进程在飞请求 ≤ 256；超额原子失败
- 目前可经 ring 提交的操作：`system.time.now`、`system.time.wait`（可取消）、`system.channel.send`、`system.channel.recv`（可取消）

### IPC Channel（`kernel/src/ipc.rs`）
- `system.channel.create` 建立一对端点；端点 v1 不可传递，进程间通道由创建方分别放入双方句柄表
- **send 两阶段**：先复制消息体与句柄值（可失败，不动句柄表），再在一把锁内复核并一次性「移出句柄 → 放进消息 → 入队」；
  队列满 `queue_full`、对端已关闭 `peer_closed`，均不移出任何句柄。只有叶子对象、且句柄带 TRANSFER 才能随消息移动
- **recv**：提交时固定接收缓冲区、句柄数组与输出字段所在的页帧，之后只经这些帧写入；交付全有或全无——
  缓冲区不足（`buffer_too_small`，返回所需大小）或接收方句柄表放不下（`table_full`）时消息留在队列
- 取消与交付由同一把锁裁决：先取消 ⇒ 消息不被消费；先交付 ⇒ 取消得到 `already_completed`
- 本端点关闭 ⇒ 其上等待的 recv 以 `cancelled` 结束、队列中的消息被销毁（其中句柄的所有权随之释放）；对端关闭 ⇒ send 与 recv 得到 `peer_closed`
- 页帧固定：请求进行中用户取消映射缓冲区，帧在请求结束后才归还；多个请求共用一个缓冲区时各自计数
- 配额：每进程排队消息体 ≤ 4 MiB、全系统 ≤ 16 MiB（超额 `quota_exceeded`，不入队、不动句柄），防止单个进程用消息耗尽内核堆

### 匿名内存（`system.memory.map` / `system.memory.unmap`）
- 在调用者进程的私有窗口内映射清零的匿名页（可选可写，**永不可执行**）或取消映射；两者都**全有或全无**：
  区间内已有映射 ⇒ `already_mapped`，取消映射的区间含空洞 ⇒ `invalid_address`，失败时地址空间与帧记账不变
- 每进程数据帧配额 8192 帧（ELF 段、栈、匿名页合计），超额 `quota_exceeded`，被拒的请求不消耗帧；单次至多 1024 页
- `system.memory.protect` 修改已映射页的权限，同样全有或全无；**可写与可执行互斥（W^X）**，可执行权限只能经它获得
- 仍被在飞请求固定的页取消映射后，帧延后到最后一次解除固定时归还

### 用户态运行时（`user/rt`，crate 名 `jasper-rt`）
- `no_std` + `alloc`，只经系统调用与内核交互；调用号与错误名在构建期从 `abi/` 登记表生成，记录布局与内核共用 `kernel-core::ring_abi`
- `entry!(main)`：入口先映射运行时自己的 256 KiB 主线程栈（下方为保护区）并切换过去，`main` 的返回值作为进程退出码；
  panic 输出位置与信息后以 101 终止进程
- 堆：复用 `kernel-core` 的链表堆算法，在私有窗口的固定区间上经 `system.memory.map` 按需增长（大请求分块映射、中途失败回滚）
- 线程：`task::spawn` / `join`，每个线程栈占一个槽位，只映射顶部 64 KiB，其下为未映射的保护区（栈溢出 ⇒ 页故障终止进程）
- `Handle`（离开作用域即关闭）、`channel`（字节 + 句柄，接收缓冲区按需扩大）、`ring`（提交、收取、取消）、`time`、`mem`、`print!` / `println!`
- 验收程序 `user/rtdemo`：集合与格式化、堆增长与全部回收、各类映射拒绝、线程、跨线程 Channel 往返（含句柄）、ring 取消与等待线程，
  共 67 步检查；另有 panic 与栈溢出两个用例，内核侧确认每个用例后页帧与对象回到基线

### 现有 Rust 库的可移植性（`user/libcheck`）
在 jasper-rt 之上直接使用 crates.io 上的库（锁定确切版本、关闭默认特性），用公开测试向量或可独立验证的往返检查：

| 库（版本） | 需要 | 检查 | 备注 |
|---|---|---|---|
| sha2 0.11.1 | `core` | FIPS 180 向量（含一百万个 `a`）、SHA-512 | 强制纯软件后端（见下） |
| crc 3.4.0 | `core` | CRC-32 / CRC-32C / CRC-16 / CRC-64 的 `123456789` 校验值、增量计算 | |
| miniz_oxide 0.9.1 | `core` + `alloc` | 手工构造的存储块、空输入 zlib 流、64 KiB 往返、改坏校验和被拒 | |
| smoltcp 0.14.0 | `core` + `alloc` | 环回设备上 TCP 连接：32 KiB 回送、SHA-256 一致、有序关闭 | 时间由调用者传入，这里用确定性虚拟时钟 |

结论：四个库都是 `no_std`，都不需要线程、线程局部存储或系统时钟。目前的两条限制：
- **SIMD**：内核还不在上下文切换时保存 SIMD / 浮点寄存器，用户程序只能走纯软件路径；`.cargo/config.toml` 以 `sha2_backend="soft"` 关闭 sha2 的 SHA-NI 实现，验收时确认用户二进制中没有 SIMD 指令
- **栈**：库的单次调用可能用掉几十 KiB 栈（实测 deflate 在 16 KiB 栈上溢出），运行时因此自备 256 KiB 主线程栈；线程栈目前 64 KiB

### `.jaso` 模块（格式 v0，Native-only）
`.jaso` 是语言无关的模块工件。v0 只有原生代码一种，**格式是实验性的、尚未冻结**（`format = 0`）：在出现第二个真实使用者之前不承诺二进制兼容。

- **文件**（`jaso/`）：80 字节头部（魔数、格式版本、种类、指令集、装载阶段、映像大小、SHA-256 摘要）+ 段目录 +
  清单 / 映像段（页对齐，r / rw / rx，不得同时可写可执行，互不共页）/ 导出表（C 调用约定的函数）/ 重定位表（只有「基址 + 加数」一种）。
  解析器对所有偏移做检查式运算，任何越界、重叠、未知取值都拒绝，从不 panic（宿主测试含 2 万次随机变异）。完整性校验只证明文件未被改动，来源认证另行设计
- **清单**：`core.name` / `core.version` / `core.abi` / `core.host` / `core.requires` / `core.exports` / `core.description`；核心键通用，
  其它键必须带命名空间（如 `web.route`），留给各自的框架解释。`core.requires` 是**请求**：装载器拿它与调用者实际授予的能力比对。
  `core.exports` 声明导出的函数名，导出表必须与它一一对应——导出是声明出来的，不是链接器顺带的（模块链接时也只导出这些名字）
- **宿主接口**：模块**不按名字导入任何符号**。需要宿主能力（输出、内存分配）时在清单中声明 `core.host = jaso.host.v0`，
  装载器调用模块的 `jaso_init`，传入一张带版本与长度的函数表（以后只在末尾追加）
- **打包**（`tools/jasopack`）：把位置无关的静态映像（static-pie）转换为 `.jaso`；出现其它种类的重定位、外部依赖或未定义符号即拒绝。`jasopack inspect` 校验并列出内容
- **装载**（`jasper-rt::module`，用户态）：校验 → 指令集 / 装载阶段 / 调用约定 → 能力 → 宿主接口表 → 映射并复制各段 → 重定位 →
  按段设权限 → `jaso_init`；任何一步失败都撤销此前的全部改动。卸载 = 取消整个映像的映射；取得的函数指针借用模块，安全代码里不能在卸载后调用
- **内核态模块**：按既定原则只做构建期组合，不在内核里装载 `.jaso`
- 验收（`user/jasodemo`）：调用各导出（读调用者内存、重定位过的只读指针表、可写数据、经宿主表分配）、两个实例数据独立、卸载后映射消失且槽位可复用；
  篡改任一字节、截断、指令集不符、装载阶段不符、能力未授予、缺宿主接口表、缺初始化入口都按对应原因被拒

### 现有库作为 `.jaso` 模块（`modules/`、`user/modhost`）
- `modules/support` 提供每个模块都需要的部分：`jaso_init`（保存宿主接口表）、把 `alloc` 的分配转给宿主接口表的全局分配器、panic 处理；
  库模块只编写 C 调用约定的导出函数，跨边界只传整数与裸指针
- 四个模块：`jaso-sha2`（SHA-256 / SHA-512）、`jaso-crc`（四种 CRC）、`jaso-deflate`（zlib 压缩 / 解压、原始 DEFLATE；交出的缓冲经 `buffer_free` 归还）、
  `jaso-net`（模块内环回设备上的 TCP 回送）。打包后分别约 29 / 7 / 53 / 49 KB
- `user/modhost` 同时装入四个模块，用与直接链接时（`user/libcheck`）相同的已知答案检查，再把它们串起来：
  压缩 → 经 TCP 回送 → SHA-256 与原压缩结果一致 → 解压 → CRC-32 与原文一致；最后全部卸载，映射消失

### 健壮性测试（`kernel-core/src/robustness.rs`）
- 固定种子的随机测试（不引入外部依赖）：ELF 变异、登记表解析、记录布局、异步环状态机与对象表对照模型、句柄世代耗尽
- 在 x86_64、32 位、AArch64、RISC-V64 上运行

## 三、构建与验收

```bash
bash scripts/accept.sh
```

验收序列（一次真实启动覆盖全部已完成里程碑）：

1. `cargo test -p kernel-core`（宿主单元测试）与 `kernel-core` 的裸机目标编译
2. 构建 `jasper-kernel` 与 BIOS 可引导镜像（`xtask`）
3. QEMU 真实启动，`isa-debug-exit` 退出码 33 表示成功
4. 按串口标记逐里程碑判定：`[JSR-BOOT]` `[JSR-TICK]` `[JSR-SCHED]` `[JSR-OBJ]` `[JSR-FRAME]` `[JSR-MAP]` `[JSR-HEAP]` `[JSR-AS]` `[JSR-USER]` 等

另有 `ISA` 一行：`kernel-core` 在 x86_64 / AArch64 / RISC-V64 / RISC-V32 四个裸机目标上编译；单元测试在 x86_64 与 32 位（i686-musl）上运行，
装有 `qemu-user` 时再在 AArch64 / RISC-V64 上运行（musl 目标 + 自带 `rust-lld` 静态链接）；未运行的会在结果中如实列出。

默认把编译与 QEMU 限制在 4 个核（`taskset -c 0-3`），可用环境变量 `JASPER_CORES` 覆盖。
