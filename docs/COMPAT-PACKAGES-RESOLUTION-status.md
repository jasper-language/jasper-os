# 兼容组件依赖求解状态

更新日期：2026-11-18。

状态：**软件规划切片已完成；LC-2、Issue #38 和兼容层整体仍未完成**。

`jasper-compat-packages` 新增确定性依赖规划器，先选择完整组件闭包，再交给现有
摘要校验、安全解包、事务激活与回滚路径。规划器本身不安装字节、不执行组件，
也不授予运行权限。

## 清单字段

现有必填字段保持不变。新增字段均为可选：

- `runtime`：候选组件要求的运行时身份，与显式平台事实精确比较；
- `abi`：语义版本约束，必须匹配平台 ABI；
- `capabilities`：运行时必须公开的具名特性或能力，不代表授权已经通过；
- `conflicts`：与候选组件版本范围互斥的组件。

`arch` 不再由解析器硬编码为单一主机架构；实际安装仍与当前目标架构比较，
不匹配会在创建暂存目录前失败。格式与版本约束错误、重复能力和重复冲突项
均在清单校验阶段失败关闭。

## 求解行为

`resolution::resolve` 接受根组件、候选清单和显式 `ResolutionPlatform`：

1. 候选按语义版本降序、摘要和名称稳定排序，保证同一输入得到同一结果；
2. 对后续依赖引入的约束重新校验已选版本，不止检查首次选择时的约束；
3. 新版本发生 `conflicts` 时回溯并尝试下一候选；
4. 缺少组件、约束无解、平台不匹配、冲突和依赖环具有不同结构化错误；
5. 成功结果按依赖优先、根组件最后排序，便于调用方逐项执行现有原子安装。

这不实现多个同名私有版本并存，也不替代 Issue #38 的 Schema 迁移、发布者密钥
轮换、企业策略、真实签名清单和真实运行验收。
