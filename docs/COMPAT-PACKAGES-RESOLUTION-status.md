# 兼容组件依赖求解状态

更新日期：2026-11-18。

状态：**软件规划切片已完成；LC-2、Issue #38 和兼容层整体仍未完成**。

`jasper-compat-packages` 新增确定性依赖规划器，并通过
`ComponentInstaller::install_resolved` 把完整计划绑定到现有摘要校验、安全解包、
事务激活与回滚路径。依赖必须已经按计划中的精确版本激活，目录中的同名同版本
歧义、版本漂移或清单/摘要身份差异都会在任何暂存目录创建前失败。规划器本身
不执行组件，也不授予运行权限。

`ComponentInstaller::rollback_resolved` 对上一版本使用同一解析和精确身份校验：
只有依赖闭包已经按计划版本激活时才切换组件状态；版本漂移、归档摘要不一致、
依赖缺失或无解均在状态切换前失败。该路径不会隐式安装或降级依赖，因此不会把
单组件回滚伪装成完整多组件事务。

## 清单字段

现有必填字段保持不变。新增字段均为可选：

- `runtime`：候选组件要求的运行时身份，与显式平台事实精确比较；
- `abi`：语义版本约束，必须匹配平台 ABI；
- `capabilities`：运行时必须公开的具名特性或能力，不代表授权已经通过；
- `conflicts`：与候选组件版本范围互斥的组件。

`arch` 不再由解析器硬编码为单一主机架构；实际安装仍与当前目标架构比较，
不匹配会在创建暂存目录前失败。格式与版本约束错误、重复能力和重复冲突项
均在清单校验阶段失败关闭。

## 求解行为

`resolution::resolve` 接受根组件、候选清单和显式 `ResolutionPlatform`：

1. 候选按语义版本降序、摘要和名称稳定排序，保证同一输入得到同一结果；
2. 对后续依赖引入的约束重新校验已选版本，不止检查首次选择时的约束；
3. 新版本发生 `conflicts` 时回溯并尝试下一候选；
4. 缺少组件、约束无解、平台不匹配、冲突和依赖环具有不同结构化错误；
5. 成功结果按依赖优先、根组件最后排序；
6. `install_resolved` 重新校验计划的根组件、完整闭包、精确激活版本和候选摘要
   身份，只有完全一致才进入原有原子安装事务，避免计划后被安装器静默重选；
7. `rollback_resolved` 对历史版本重新执行相同的不变量校验，并在任何状态写入前
   拒绝版本、摘要或依赖闭包漂移。

这不实现多个同名私有版本并存，也不替代 Issue #38 的 Schema 迁移、发布者密钥
轮换、企业策略、真实签名清单和真实运行验收。
